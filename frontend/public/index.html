Engineering Solution · K2

Failure memory changes call behavior

A 50% failure threshold after at least three calls opens the breaker. It waits 15 seconds, allows one genuine recovery probe, and closes only when that probe succeeds.

Technical details

Opossum uses a 3-second timeout, 50% error threshold, minimum volume of 3, and a 15-second reset timeout. Controlled fault modes are request-scoped and enabled only in the local lab environment. Reset is refused while a protected call is active.

Engineering Challenge

A slow dependency makes requests pile up

Immediate retries can increase pressure and synchronize many callers. Invalid requests will not recover by repeating them.

Engineering Solution · J2

Backoff gives recovery time; jitter spreads callers

Only transient failures are retried. Every run is bounded by three attempts and an overall deadline.

Technical details

Server-sent events stream each attempt and wait as they occur. Base waits are 200 ms then 400 ms; each adds 0–100 ms of genuine random jitter. HTTP 400 stops immediately.

Engineering Solution · L

Separate allocations contain slow work

The Recommendation Pool admits two and quickly rejects excess work. The independent Payment Pool retains its own slot and completes normally.

Technical details

These are two genuinely independent in-memory concurrency controls in one Lab Service instance: Recommendation limit 2 and simulated Payment limit 1. They are not cluster-wide limits and this lab never invokes real payment processing.
